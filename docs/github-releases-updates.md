# Обновления через GitHub Releases

Настройки → Проверить обновления. Проверка ручная, без фоновых запросов и токенов. Используется публичный API `/repos/vahmurka1975/prichastie-app/releases/latest`. Черновики и prerelease не предлагаются. Есть сообщения об отсутствии релизов, сети, ограничении запросов и некорректном ответе.

## Публикация обновления

1. В `app/build.gradle.kts` увеличьте оба поля: целочисленный `versionCode` и `versionName`. В исходной базе они равны `1` и `1.0`; для следующей версии можно использовать `2` и `1.1.0`.
2. Android Studio → Generate Signed App Bundle / APK → APK. Соберите один универсальный подписанный release APK постоянным ключом. Не добавляйте ключи и пароли в Git; храните резервную копию ключа отдельно.
3. https://github.com/vahmurka1975/prichastie-app/releases/new → новый стабильный релиз с тегом, совпадающим с versionName, например `v1.1.0`. Поддерживаются числовые версии из 1–4 компонентов с необязательным v/V. Например, 1.10.0 новее 1.9.0.
4. Приложите ровно один универсальный подписанный `.apk`, например `prichastie-1.1.0.apk`. Не AAB, не набор ABI APK. Дождитесь окончания загрузки.
5. Опубликуйте релиз: не Draft, не Pre-release; назначьте Latest.
6. На телефоне с предыдущей версией: Настройки → Проверить обновления → Скачать APK. Откроется браузер. После загрузки откройте файл и подтвердите установку Android. При необходимости разрешите установку из браузера/файлового менеджера.

Приложение не скачивает APK в фоне и не устанавливает его самостоятельно. Не требуются REQUEST_INSTALL_PACKAGES, FileProvider или дополнительные библиотеки. Ссылки принимаются только по HTTPS из releases/download этого репозитория на github.com; последующими редиректами на CDN управляет браузер. Если APK нет или APK несколько, приложение не выбирает произвольный файл.

## Подпись и данные

Обновление поверх установленного приложения требует тот же applicationId (`ru.example.prichastie`), тот же ключ подписи (либо поддерживаемую Android ротацию) и допустимый versionCode. При каждой новой публикации увеличивайте versionCode. При обновлении без удаления данные и прогресс сохраняются. Удалять приложение перед обновлением не нужно.

Debug APK и release APK с другим ключом несовместимы. Если сейчас стоит debug APK, заранее спланируйте перенос данных и переход на постоянную подпись: не удаляйте рабочее приложение вслепую. Проверка сравнивает versionName с тегом; versionCode и подпись APK проверяет системный установщик, а не этот клиент. Не заменяйте APK под прежним тегом: публикуйте новую версию.

Первая установка с этой функцией выполняется вручную. Следующие версии смогут проверяться из Настроек.

## Проверка перед слиянием

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

Добавлены unit-тесты сравнения версий. В среде внесения правок Gradle и эмулятор не запускались. Вручную проверьте: нет сети; нет релизов; версии равны/установленная новее; новый релиз с одним APK; отсутствие APK; несколько APK; отмена диалога; скачивание и обновление поверх старой версии с тем же ключом.
