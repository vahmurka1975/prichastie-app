# Обновления через GitHub Releases

Настройки → Проверить обновления. Проверка ручная, без фоновых запросов и токенов. Используется публичный API `/repos/vahmurka1975/prichastie-app/releases/latest`. Черновики и prerelease не предлагаются. Есть сообщения об отсутствии релизов, сети, ограничении запросов и некорректном ответе.

## Как работает обновление в приложении

1. Настройки → Проверить обновления. Если найден более новый релиз, появится диалог.
2. Кнопка «Скачать» запускает загрузку APK прямо в приложении. Показывается прогресс (загружено / всего). Загрузку можно отменить.
3. После загрузки APK проверяется: это пакет `ru.example.prichastie`, его `versionCode` выше установленного, подпись совпадает с установленным приложением. При ошибке показывается понятное сообщение, файл удаляется.
4. Если проверка пройдена, автоматически открывается системный установщик Android. Остаётся подтвердить установку.
5. Если Android ещё не разрешил этому приложению устанавливать пакеты, приложение сообщит об этом и откроет настройки. После выдачи разрешения вернитесь в приложение и повторите установку: скачанный файл сохранён.

Файл хранится во внутреннем кэше `cache/updates/` и передаётся установщику через `FileProvider` (authority `${applicationId}.updates`, пути в `res/xml/update_file_paths.xml`). В манифесте объявлено разрешение `REQUEST_INSTALL_PACKAGES`.

Скачивание разрешено только по HTTPS с `github.com` и `*.githubusercontent.com`. Редиректы (до 6) проверяются на каждом шаге. Если в релизе нет APK или их несколько, приложение не выбирает произвольный файл.

## Публикация обновления

1. В `app/build.gradle.kts` увеличьте оба поля: целочисленный `versionCode` и `versionName`. Текущие значения в коде: `5` и `1.0.5`; для следующего релиза используйте не меньше `6` и `1.0.6`.
2. Android Studio → Generate Signed App Bundle / APK → APK. Соберите один универсальный подписанный release APK постоянным ключом. Не добавляйте ключи и пароли в Git; храните резервную копию ключа отдельно. Сборка читает подпись из `keystore.properties` или переменных окружения `RELEASE_*`.
3. Закоммитьте и отправьте изменения в `main` (через Pull Request), затем откройте https://github.com/vahmurka1975/prichastie-app/releases/new и создайте стабильный релиз с тегом, совпадающим с versionName, например `v1.0.6`. Тег должен указывать на коммит с этой версией кода. Поддерживаются числовые версии из 1–4 компонентов с необязательным v/V. Например, 1.10.0 новее 1.9.0.
4. Приложите ровно один универсальный подписанный `.apk`, например `prichastie-1.0.6.apk`. Не AAB, не набор ABI APK. Дождитесь окончания загрузки.
5. Опубликуйте релиз: не Draft, не Pre-release; назначьте Latest.
6. На телефоне с предыдущей версией: Настройки → Проверить обновления → Скачать → подтвердить установку.

## Подпись и данные

Обновление поверх установленного приложения требует тот же applicationId (`ru.example.prichastie`), тот же ключ подписи (либо поддерживаемую Android ротацию) и больший versionCode. При каждой новой публикации увеличивайте versionCode. При обновлении без удаления данные и прогресс сохраняются. Удалять приложение перед обновлением не нужно.

Debug APK и release APK с другим ключом несовместимы. Если сейчас стоит debug APK, заранее спланируйте переход на постоянную подпись: не удаляйте рабочее приложение вслепую. Перед установкой приложение само сверяет пакет, versionCode и подпись; окончательную проверку выполняет системный установщик. Не заменяйте APK под прежним тегом: публикуйте новую версию.

Обновление с автоматическим открытием установщика работает начиная с версии, в которой эта функция есть. Версии без неё нужно обновить вручную один раз.

## Проверка перед слиянием

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

Вручную проверьте: нет сети; нет релизов; версии равны/установленная новее; новый релиз с одним APK; отсутствие APK; несколько APK; отмена загрузки; обрыв сети во время загрузки; отказ в разрешении на установку и повтор после его выдачи; отмена системного установщика; обновление поверх старой версии с тем же ключом.
